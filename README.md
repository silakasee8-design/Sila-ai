# SILA AI — deployment and accounts

## Render deployment

1. Push this repository to GitHub and create a new **Blueprint** in Render using `render.yaml`.
2. Render will create the web service and PostgreSQL database. If your Render plan does not support the database plan in the blueprint, create a PostgreSQL database manually and connect its internal connection string as `DATABASE_URL`.
3. Set `OPENAI_API_KEY` in the web service environment. `JWT_SECRET` is generated by the blueprint; do not replace it with a public value.
4. Deploy and check `https://YOUR-SERVICE.onrender.com/api/health`. It should report `aiConfigured: true` and `databaseConfigured: true`.

The application runs the small schema migration automatically on startup. Database-backed history requires PostgreSQL; browser local history is no longer used for authenticated conversations.

## Accounts and security

Users can register with an email and a password of at least eight characters. Authentication uses an HTTP-only cookie and bcrypt password hashes. Never commit `.env`, API keys, passwords, or `DATABASE_URL` to Git.

Required variables:

```env
PORT=3000
OPENAI_API_KEY=your_key
OPENAI_MODEL=gpt-4o-mini
DATABASE_URL=postgres://...
JWT_SECRET=long_random_secret
```

Use HTTPS in production. Render provides HTTPS automatically. For production use, consider adding email verification, password reset, rate limiting, and a managed identity provider before opening registration publicly.
